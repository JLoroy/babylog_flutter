# Babylog Android Audit (2026-02-03)

## Scope
- Android only.
- Goal: get back to Play Console activity before 2026-03-10.
- Package: com.eranova.babylog.
- Last known release: 1.0.2+3 (versionCode 3) on 2025-01-09, Internal Testing.

## Snapshot
- Flutter app with Firebase Auth + Firestore + Realtime Database.
- OpenAI API calls from the client for chat and audio transcription.
- Audio recording feature (record + audioplayers).
- Android build uses Kotlin DSL, AGP 8.8.0, Gradle 8.10.2, Kotlin 1.9.22.
- targetSdk 34, minSdk 23.

## Critical Blockers (must fix before release)
1. Release build likely has no INTERNET permission.
   - Only debug/profile manifests include INTERNET; main manifest has only RECORD_AUDIO.
   - Fix: add android.permission.INTERNET to android/app/src/main/AndroidManifest.xml.

2. Audio recording path is invalid.
   - recorder.dart uses hardcoded path 'your/app/directory/...'.
   - This will fail on-device. Use path_provider to create a valid app directory path.

3. OpenAI API key handling is not safe for production.
   - A dev API key is fetched from Firestore and used on-device.
   - User BYOK keys are stored in Firestore (not secure; also creates data liability).
   - Fix: remove any secret keys from client. Use backend proxy with per-user auth, or BYOK stored locally with secure storage and never synced.

4. Release signing config hardcoded to a machine path.
   - android/app/build.gradle.kts points to H:/My Drive/...eranova_upload.jks.
   - This is not portable and will break in CI or any other machine.
   - Fix: use key.properties or environment variables for store file location.

5. Data deletion is incomplete.
   - "Delete Account" deletes only events; user/assistant docs remain.
   - Play Console requires a clear data deletion path if you collect personal data.
   - Fix: delete user doc, assistant membership, and orphaned assistant docs (or disable account creation).

## High Risk
1. OpenAI usage and data safety.
   - Audio and text data sent to OpenAI; must be disclosed in Data Safety section and privacy policy.
   - If using a backend, define retention and processing.

2. Firebase security rules are not in repo.
   - There is no rules file or reference here, so risk of overly permissive access.
   - Fix: verify Firestore/RTDB rules, ensure users cannot read/write other users' data.

3. Firebase google-services plugin not configured.
   - google-services.json exists, but no com.google.gms.google-services plugin in Gradle.
   - If analytics/auth/other features depend on it, behavior may be broken in release.

## Medium Risk / Quality
1. Dependency hygiene.
   - http is imported but not listed in pubspec.yaml.
   - win32 should be a desktop-only dependency, not in core dependencies for Android.

2. Encoding/locale issues.
   - releasenotes.md and systemPrompt contain broken accents (likely encoding mismatch).

3. UI and stability.
   - Errors are printed to console; no user-visible error handling for many failures.
   - No crash reporting or analytics visibility.

4. No tests beyond default widget_test.
   - Risky for refactors and publish cadence.
